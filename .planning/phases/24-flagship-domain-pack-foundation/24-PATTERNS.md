## Note on this phase's shape

Per RESEARCH.md, this phase adds **zero new framework code** — the deliverable is (a) a new
`domains/agent-security/` pack (generated by `klake domain new` then hand-edited), (b) a
human-authored findings document, and (c) a sequence of existing CLI/pipeline-function
invocations (crawl, process, enrich, quality-audit, project lifecycle) run against the new
domain. There is no controller/service/model *code* to write from scratch — the "files to
create" are domain-pack **data/config files** (YAML, Jinja2 prompts, one stdlib-only validator
module) whose closest analogs are the existing `domains/aviation/*` pack (same non-healthcare,
generic-precedent shape) and, for `filters.yaml`-shaped design context only (not to be authored
this phase — see Phase Boundary), `domains/healthcare/filters.yaml`.

One CLI fix is optionally in-scope per RESEARCH.md's Open Question 1 (`--source-url` on
`klake upload`) — its analog is `cmd_project_new`'s existing argument-passing shape in `cli/app.py`.

RMF 1.0 if the HTML landing page isn't judged substantively equivalent). CISA's source needs an
explicit drop/mirror/upload decision per Pitfall 5 before this file is finalized.

### `domains/agent-security/validators/validate.py` (`AgentSecurityValidator`) (utility, transform)

**Analog:** `domains/aviation/validators/validate.py` (full file, 96 lines — read and reproduced above)

**Imports pattern (lines 1-14):**
```python
from __future__ import annotations

import re
from dataclasses import dataclass, field
from typing import Any
```
Module docstring (lines 1-8) states the hard constraint: **stdlib-only imports, no
`knowledge_lake` imports** — the module is loaded dynamically via `importlib.util` without package
context (this is a `DomainLoader` requirement, not a style choice — violating it will break pack
loading).

**Core pattern — regex constants (lines 16-48):** aviation defines domain-identifier regexes
(`N_NUMBER_PATTERN`, `CFR_CITATION_PATTERN`, `CFR_MENTION_PATTERN`) plus a term list
(`AVIATION_TERMS` → `AVIATION_TERM_PATTERN`, case-insensitive alternation). For
`AgentSecurityValidator`, RESEARCH.md's Code Examples section names the concrete analogs to build:
- Permission-scope pattern: `re.compile(r"\b\w+:\w+\b")` (e.g. `read:documents`)
- Tool-identifier pattern: `re.compile(r"\bmcp__\w+__\w+\b")`
- CVSS-vector pattern: `re.compile(r"\bAV:[NAL]/AC:[LH]/PR:[NLH]\b")`
- Domain-term list: `agent, tool, permission, scope, prompt injection, mcp, oauth, rbac, abac, tool-poisoning, confused deputy, ...` (mirrors D-03's taxonomy anchors)

**Core pattern — `ValidationResult` dataclass (lines 51-57):**
```python
@dataclass
class ValidationResult:
    """Result from AviationValidator.validate_document()."""
    passed: bool
    warnings: list[str] = field(default_factory=list)
    errors: list[str] = field(default_factory=list)
```
Copy verbatim (rename docstring reference only).

**Core pattern — validator class + `validate_document()` method (lines 60-95):**
```python
class AviationValidator:
    def validate_document(self, document: dict[str, Any]) -> ValidationResult:
        text: str = document.get("text", "") or ""
        warnings: list[str] = []
        errors: list[str] = []

        # Check 1: empty document — fatal
        if not text.strip():
            errors.append("empty document")
            return ValidationResult(passed=False, warnings=warnings, errors=errors)

        # Check 2: no domain term/identifier detected — non-fatal warning
        has_term = bool(AVIATION_TERM_PATTERN.search(text))
        has_n_number = bool(N_NUMBER_PATTERN.search(text))
        has_cfr_citation = bool(CFR_CITATION_PATTERN.search(text))
        if not (has_term or has_n_number or has_cfr_citation):
            warnings.append("no_aviation_terms_detected")

        # Check 3: malformed pattern — non-fatal warning
        if CFR_MENTION_PATTERN.search(text) and not has_cfr_citation:
            warnings.append("malformed_regulation_citation")

        return ValidationResult(passed=len(errors) == 0, warnings=warnings, errors=errors)
```
**Class-naming convention (hard requirement):** `DomainLoader` finds the validator class by name
suffix `Validator` — the new class MUST be named `AgentSecurityValidator` and expose
`validate_document(document: dict[str, Any]) -> ValidationResult` with this exact signature.
Reuse the same 3-check shape: (1) empty-doc fatal check, (2) no-domain-term/identifier non-fatal
warning (`no_agent_security_terms_detected` or similar), (3) malformed-pattern non-fatal warning
(e.g. bare "CVSS" mention without a well-formed vector string, mirroring aviation's bare-"CFR" check).

### `.planning/phases/24-flagship-domain-pack-foundation/24-GATE-REVIEW-FINDINGS.md` (doc, batch)

**No direct file analog** — this is a new artifact *type* for this project (first human-authored
gate-review findings doc). Structural precedent is procedural, not a file to copy:
- **Source of the underlying query pattern:** RESEARCH.md's "Pattern 3" (reproduced below) —
  query `Artifact` rows where `artifact_type == "chunk"`, joined to `Source.domain ==
  "agent-security"`, filtered to `metadata_["substance_passed"] is False`.
- **Source of the report-only discipline being documented:** Phase 19/20's report-mode-before-enforce
  precedent (no specific file — this is a process convention, see D-04's own rationale).
- **Required content shape (from D-04):** rejection count/rate, a real inspectable sample of
  rejected chunks (not paraphrased), an explicit judgment on whether healthcare-tuned heuristics
  are wrongly dropping domain-specific short/structured content, and a handoff note pointing at
  Phase 26.

```python
# Query pattern (RESEARCH.md Pattern 3) — the concrete mechanism to build the findings sample from
from sqlalchemy import select
from knowledge_lake.registry.models import Artifact, Source
from knowledge_lake.registry.db import get_session

with get_session() as session:
    agent_security_source_ids = [
        s.id for s in session.execute(
            select(Source).where(Source.domain == "agent-security")
        ).scalars()
    ]
    rejected = session.execute(
        select(Artifact)
        .where(Artifact.artifact_type == "chunk")
        .where(Artifact.source_id.in_(agent_security_source_ids))
    ).scalars().all()
    rejected_sample = [
        a for a in rejected if a.metadata_.get("substance_passed") is False
    ][:20]
```

## Shared Patterns

### Scaffold-then-edit (not from-scratch authoring)
**Source:** `src/knowledge_lake/domains/scaffold.py` (`scaffold_domain()` / `klake domain new`)
**Apply to:** All 7 domain pack files above.
Do not hand-author any of these files from a blank editor. Run `uv run klake domain new
agent-security` first — it generates every file listed above with the domain name already
substituted (`__DOMAIN__` → `agent-security`, `__PASCAL__` → `AgentSecurity`), including the
prompt-injection-defense clause in both `.j2` prompts by default. All subsequent work is *editing*
the generated files to add D-02/D-03-specific content, not creating new files.

### Prompt-injection defense clause (must survive customization)
**Source:** `domains/aviation/prompts/enrich.j2` lines 26-28 and `qa_generation.j2` lines 20-22
(both quoted above)
**Apply to:** `domains/agent-security/prompts/enrich.j2`, `domains/agent-security/prompts/qa_generation.j2`
Given this domain's dual-use, attack-technique subject matter (D-06), this existing clause is
more load-bearing here than for any prior domain pack — RESEARCH.md's Security Domain table flags
it explicitly. Never remove or weaken it while customizing prompt content.

### Two distinct "domain" filters that share a string value (operational, not a file pattern)
**Source:** RESEARCH.md Pattern 2 (`Source.domain` column vs. `settings.domain.domain_name`
pydantic-settings field)
**Apply to:** every CLI invocation in the ingestion sequence — `--domain agent-security` for
`crawl-all`/`quality-audit` (source-selection), `KLAKE_DOMAIN__DOMAIN_NAME=agent-security` env var
for `process-crawled`/`enrich`/`clean`/`chunk` (prompt/filter resolution). Not a code pattern to
copy, but a sequencing discipline every plan step in this phase must apply consistently.

### Report-mode-before-enforce discipline
**Source:** `src/knowledge_lake/config/settings.py:326` (`gate_mode: Literal["enforce",
"report"] = "enforce"`) and `pipeline/chunk.py:353,424,473` (where it's consumed)
**Apply to:** the entire real ingestion sequence (`process-crawled`), not just the audit/measurement
step — per RESEARCH.md Pitfall 4, setting `gate_mode=report` only before `quality-audit --full` is
insufficient; it must be set before `process_crawled()` is first invoked so rejected chunks are
actually persisted and later queryable.
