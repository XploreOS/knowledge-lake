<objective>
Close 24-VERIFICATION.md gap #8's root cause: `EnrichmentResult.document_type`'s `Field(max_length=100)` rejects a real subset of this domain's legitimately-longer LLM-generated document types with no retry (by design — src/knowledge_lake/pipeline/enrich.py lines 253-269 deliberately avoid a 3x budget-burn retry on "truly unrecoverable" validation failures), silently producing `status: "skipped_enrichment_failed"` with no artifact created; and `cmd_enrich` (src/knowledge_lake/cli/app.py:358-411) exits 0 regardless, because it only raises `typer.Exit(code=1)` for `ValueError`/`LookupError` — never for an internal skipped/failed enrichment status. Together these two defects let 90 of 200 agent-security `cleaned_document` artifacts silently miss their `enriched_document` sibling while 24-02-SUMMARY.md's client-side loop script reported "0 failures" based on exit code alone.

This plan fixes both defects at their source with regression tests proving each fix. It does NOT re-run enrichment against the live corpus — that is Plan 24-06's job, which depends on this plan's fix landing first (re-running before the fix would just reproduce the same 90 failures).

Purpose: make the two root-cause defects (a Pydantic validation bound that silently discards a legitimate subset of enrichment output, and a CLI command that silently reports success on internal failure) permanently impossible to reintroduce, via tests that fail red without the fix.

Output: `src/knowledge_lake/pipeline/enrich.py` (new `_truncate_document_type` validator), `src/knowledge_lake/cli/app.py` (`cmd_enrich`'s new skipped-status exit-code check), `tests/unit/test_enrich.py` (extended), `tests/unit/test_cli_enrich.py` (new).
</objective>
