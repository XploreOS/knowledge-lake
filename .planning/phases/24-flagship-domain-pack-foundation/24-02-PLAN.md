<objective>
Run the real, end-to-end ingestion of the flagship `agent-security` corpus: register every `sources.yaml` entry as a `Source` row (including the PDF-only entry via the Pitfall 1 workaround), crawl every crawl-type source, batch-process everything through parse→clean→chunk→dedup→embed→index in `gate_mode="report"` so rejected chunks are persisted and inspectable, and close the `process_crawled()` enrich gap (Pitfall 2) by running `enrich_document()` for every resulting `cleaned_document` artifact.

This plan owns no formal REQUIREMENTS.md ID (see 24-01-PLAN.md's objective for the same note). It is scoped to ROADMAP.md Success Criterion 2 in full ("real AI-agent-security-and-permission sources are ingested end-to-end through the existing parse → clean → chunk → enrich → embed → index pipeline") and is the load-bearing prerequisite for Success Criterion 3 (Plan 24-03's report-only gate findings depend on this plan's `gate_mode="report"` discipline) and Success Criterion 4 (Plan 24-04's Dataset Specification depends on this plan's real `Source` IDs, per Pitfall 6).

Implements CONTEXT.md D-04's report-only-run half directly (the human-reviewed findings document itself is Plan 24-03's job).

Purpose: Give every later v2.7 phase (25-31) a genuine, non-healthcare corpus to build and test against instead of synthetic fixtures — and produce the real rejected-chunk data Plan 24-03's findings document needs.

Output: Real `Source`/`Artifact` rows for the `agent-security` domain across every pipeline stage, and new points in the `klake_chunks` Qdrant collection. No repository files are modified by this plan — its output is registry/storage/vector-index state.
</objective>
