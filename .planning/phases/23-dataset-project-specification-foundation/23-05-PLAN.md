| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-23-14 | Tampering | Mass-assignment via SpecVersionCreate.spec's free-form dict | high | mitigate | `spec` is `dict` typed at the Pydantic-schema layer (necessarily loose, since its own shape varies by SPEC-01's field list) but is immediately re-validated field-by-field against `DatasetSpecFields` (`extra="forbid"`) inside `create_spec_version()` (Plan 23-03) BEFORE any DB write — the route itself never persists the raw body. |
| T-23-15 | Tampering | ProjectTransitionRequest.to_state accepting an out-of-vocabulary string | medium | mitigate | Pydantic `pattern=r"^(draft\|configured\|...\|archived)$"` rejects any value outside the 11-state vocabulary at the schema layer (422) before `transition_project()` is ever called — defence-in-depth alongside `_TRANSITIONS`'s own runtime check. |
| T-23-16 | Information Disclosure | 409 illegal-transition detail body exposing internal state-machine structure | low | accept | The full transition graph is fixed, published business logic (D-04), not sensitive data — same disposition as RESEARCH.md's Known Threat Patterns table and Plan 23-02's T-23-05. |
